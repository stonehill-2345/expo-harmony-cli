# I0 shared-host acceptance

SDK-owned assembly of the real B Constants/Asset packages on the Core-v1 host.
This is a test fixture, not prebuild/autolinking or an application compatibility
shim. The default Core-only generator/entry remains available. `--i0` uses the
existing public `expo` / `registerRootComponent` entry with a test screen that
runs module checks **after** the unchanged 50 Core assertions.

## Prepare and build

Use Node22, the existing TypeScript5.9.2 tooling environment and the approved
`expo-rnoh-0.82.30-core-v1-v3` HAR (SHA256
`0e0cf3dbb5b2e510f49c819ff5db2f43ad5a5918d38e840cc2714055c9f6fd83`).
Use a **new** fixture directory. On macOS pass the canonical `/private/tmp` path
to Metro, not the `/tmp` symlink. Do not edit installed dependencies.

```sh
node packages/expo-modules-core/harmony/example/tools/prepare-fixture.cjs \
  --sdk-root "$PWD" --fixture-root "$FIXTURE" --tooling-root "$TOOLING" \
  --har "$HAR" --i0
node packages/expo-modules-core/harmony/example/tools/verify-install.cjs "$FIXTURE"
DEVECO_HOME=/Applications/DevEco-Studio.app/Contents \
  bash packages/expo-modules-core/harmony/example/tools/build-i0.sh "$FIXTURE" release
```

Build outputs are `artifacts/i0-{release,debug}.hap`. Archive/hash them before
another build of the same mode (especially a diagnostic build). Release is a
native release HAP with `dev:false`, embedded bundle and RNOH-copied static
assets. `app.config` is generated by Constants' official public-config script,
not handwritten. Source modules and Metro JS are transpiled from this SDK;
existing declarations are retained except Core Platform (not a full type build).

For Debug, start both real servers, expose ports8081/18080 with HDC `rport`, and
build/install the debug HAP:

```sh
node packages/expo-asset/harmony/example/server.mjs
node packages/expo-modules-core/harmony/example/tools/serve-i0.cjs "$FIXTURE"
DEVECO_HOME=/Applications/DevEco-Studio.app/Contents \
  bash packages/expo-modules-core/harmony/example/tools/build-i0.sh "$FIXTURE" debug
```

Debug loads `http://127.0.0.1:8081/expo-entry.bundle?platform=harmony&dev=true&minify=false`
using `MetroJSBundleProvider`; the server uses Expo's real `/message` websocket.
No SourceCode override, embedded-dev exception suppression or app Metro config.
The test application ID is `dev.expo.harmony.i0`. Only operate this test app.

## Tests and result boundaries

Set `EXPO_HARMONY_TOOLING_ROOT`, `EXPO_HARMONY_EXAMPLE_ROOT`, and
`EXPO_I0_FIXTURE_ROOT` to the appropriate installed/tooling paths; put the SDK
CMake directory on PATH. Run Node tests **serially before HAP build/install**:
startup/asset tests rewrite the raw bundle. Then always rebuild the chosen mode.

```sh
node --test --test-concurrency=1 packages/expo-modules-core/harmony/example/tests/*.test.cjs
node packages/expo-modules-core/harmony/example/tools/check-i0-log.cjs "$LOG" release --reload
node packages/expo-modules-core/harmony/example/tools/check-i0-log.cjs "$LOG" debug --reload
```

The I0 checker also invokes the existing 50-item Core checker and rejects missing
module results, wrong modes/session IDs and old Runtime Asset callbacks.
`i0-device-log.test.cjs` uses preserved real evidence: accepting Release and
**rejecting** the known Debug failure is a passing *checker test*, not passing
Debug lifecycle acceptance.

`ObservedAssetPackage.ets` is diagnostic only and **not used by normal assembly**.
It calls the unchanged B implementation and adds native lifetime timestamps;
use a separately labeled HAP, not as production-package acceptance evidence.

Current blocker and source/artifact identities are recorded in
`docs/harmony-sdk54/evidence/2026-09-20-i0/`. Standard startup success does not
certify I0 lifecycle completion, Router, prebuild, or the full Expo SDK.
