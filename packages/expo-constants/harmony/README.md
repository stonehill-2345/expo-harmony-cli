# expo-constants Harmony

This directory contains the Harmony backend for expo-constants 18.0.14 on
RNOH 0.82.30. It registers one native TurboModule named
`ExponentConstants`; application JavaScript continues to import
`expo-constants` normally.

## Exports

- ArkTS package: `ExponentConstantsPackage` from `index.ets`.
- C++ package: `expo::constants::harmony::ExponentConstantsPackage` from
  `src/main/cpp/ExponentConstantsPackage.h`.
- CMake target: `rnoh_expo_constants`.

The host must package the public Expo config generated by
`scripts/getAppConfig.js` as the raw file `app.config`. Missing config maps to a
null native manifest; malformed config is an error. The module reads device,
bundle, window, font, debug-mode and ArkWeb user-agent data from Harmony APIs.
It does not synthesize Expo Go fields or an application config.

Host C++ wiring adds this directory after RNOH, links
`rnoh_expo_constants`, and constructs `ExponentConstantsPackage` in the shared
PackageProvider. Host ArkTS wiring adds the exported package to the RNOH package
list. Those shared-host edits belong to lane A. Both package constructors take
the real RNOH package context: C++
`std::make_shared<expo::constants::harmony::ExponentConstantsPackage>(ctx)` and
ArkTS `new ExponentConstantsPackage(ctx)`.

Public API checks and an independent system-data oracle are in `example/`.
The joint [lane B handoff](../../expo-asset/harmony/example/README.md) describes
assembly and the unfulfilled A0/S1 prerequisite. These checks are not yet public
API device acceptance evidence.

## Local checks

From the repository root, run the data tests:

```sh
node --experimental-strip-types --test \
  packages/expo-constants/harmony/tests/constants-data.test.mjs
```

For the native interface compile check, use a fresh build directory and a full
RNOH 0.82.30 package directory:

```sh
cmake -S packages/expo-constants/harmony/tests/rnoh -B /tmp/expo-constants-rnoh \
  -G Ninja -DCMAKE_TOOLCHAIN_FILE="$OH_NATIVE_SDK/build/cmake/ohos.toolchain.cmake" \
  -DCMAKE_MAKE_PROGRAM="$OH_NATIVE_SDK/build-tools/cmake/bin/ninja" \
  -DOHOS_ARCH=arm64-v8a -DCMAKE_BUILD_TYPE=Debug \
  -DRNOH_PACKAGE_DIR="$RNOH_PACKAGE_DIR"
cmake --build /tmp/expo-constants-rnoh \
  --target expo_constants_package_compile_check -j 4
```

These checks do not prove direct RNOH lookup, Core public lookup, or device API
results. Record those layers separately.
