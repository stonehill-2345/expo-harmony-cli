# M0 消费者声明来源闭合设计

继续原M0-02/03已授权实施，沿用feat/V1.7.0现场、不提交、不下载、不修改旧封存。M0当前66%(4/6)，接受仍按原条件复核。

根因：consumer-v1只采用原source解析Map及配置typeRoots；外部声明的显式type directive不能按其manifest和固定锁访问已验证归档。真实两个上下文79/5条诊断；61条2307中57为Node内置，6条2688中只有xml2js的node引用能由现有manifest依赖及固定锁选择22.14.0。minipass四条与spawn-async一条只见发布者开发依赖且对应selector缺锁，不能选另一版本顶替；getenv/semver不能借其他workspace的devDependencies补身份。

方案：显式--type-root-isolation consumer-v2，保留consumer-v1及默认完整字节兼容。loader复用已验证的全部声明归档和固定yarn.lock创建createDeclarationContext，开启已有sourceProvenance/declaredTypes/transitive策略；builder接收sourceContext与policy，仅v2传入core的consumerProjection。模块解析先使用原固定source映射，再尝试已有resolver；显式type directive先按配置原生解析，再由from对应声明包的固定manifest/lock选择归档。返回source路径必须位于已核files，hash与input一致；无宿主node_modules回退。

Node内置的node-global-context不是source，禁止把声明文件伪作外部模块返回。Node根仅经实际显式type directive或原配置授权的自动类型选择进入Program；本批不新增无条件Node自动根。合法显式node引用加载完整文件与安全闭包，在同一个消费Program中产生原生全局/ambient语言效果；缺失引用按原生2688与逐来源结果保留，不能以别处已加载同名包作为其身份接受。

消费者上下文新增source resolution记录：kind(module/type-directive)、request、from、原resolver结果、实际选择路径及输入hash，明确投影/peer/传递来源的未安装边界。上下文graph与原17张表分离，所有旧USE ID/source/target及共享图保持。当前212使用和历史194仍逐条验证真实符号绑定；更完整类型展开后新诊断、类型预算等如实保留，不预设诊断全消或M0关闭。

来源授权区分：原fixed-source-map和原生相对解析可使用已核workspace inputs；sourceContext为归档解析器，其返回的source必须在snapshot.files授权集合且hash一致，不能借workspace路径前缀免检。除入口之外，实际进入Program的每个外部声明子文件（含三斜线path闭包）也须与snapshot.files和已核inputs双重核验，缺行或坏hash明确拒绝。此前仅验返回入口的建议不完整，防再发为入口和Program实际输入同时验证。

原生外部path引用限同一归档身份，跨归档或工作区必须拒绝；模块依赖使用已有resolver选择。loader交给来源上下文的workspaceFiles仅含已核fixed-git-blob，声明及配置归档由各自入口重建，避免已materialize归档目录再次碰撞；公开loaded.files和来源证据保持全量。

替代方案评估：无条件加@types/node根会跳过消费身份和types配置，拒绝；修改共享语义图会扩大本批并破坏前批对照，留后续；在消费者独立checker按固定请求来源解析，复用已有选择规则，采用。

验收：先红测证明合法外部type directive可加载且实际Buffer/Node builtin类型生效；缺锁、歧义、越界路径、坏hash、types opt-out、显式引用以及两个消费者不污染；默认与consumer-v1不变；v2真实生成、重复/check、删来源记录真实CLI拒绝；17表分片不变、历史194/当前212逐ID、所有Program输入与类型引用闭合、独立审查及封存。旧仓库摘要绝对路径FAIL保持，写出新摘要后重查。
