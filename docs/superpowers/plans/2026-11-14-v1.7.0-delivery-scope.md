# 1.7.0 支持范围与收敛交付计划

日期：2026-11-14。状态：用户已确认版本方向与首批范围；产品尚未最终验收。

> 执行方式：B/C 文件归属、任务顺序及交接统一按 [当前 B/C 执行计划](2026-11-14-v1.7.0-bc-execution.md)，或在当前会话顺序执行；不自动创建子代理、不联系其他会话、不提交或发布。实施可使用 executing-plans。本文是版本范围及交付计划，具体缺陷先复现再最小修复，不预设未经核查的代码方案。

## 1. 最新决策与优先级

用户确认：1.7.0 交付“开发流程完整、支持模块范围明确的 Expo Harmony SDK”。首批采用已有模块及原样 default 所需能力，不额外纳入相机/扫码、定位、文件读写、数据库、音视频、通知等业务扩展。若其中某项是首批能力的实际依赖，仍须交付所需依赖，不扩大为整包支持。

本文覆盖旧总设计、总计划、COMMON、角色执行单及同分支计划中的版本范围、阶段串行关系、全量 M7/M8 发布条件和每轮报告要求。技术架构、安全、真实证据和候选一致性要求继续有效。旧文档描述保留为历史或长期路线，不代表当前版本全部必达。

目标：标准 Expo 开发流程、首批明确能力、真实发行物消费形成闭环。全量 SDK54 生态适配继续作为后续路线，不作为 1.7.0 发布前置条件。
架构：复用已实现的 create、Expo CLI、配置插件、工程生成、Autolinking、Core、Metro 和候选/验证工具；不恢复消费端 patch、源码替换或独立 CLI 补平台能力。
工具链：SDK54、React 19.1.1、RN 0.82.1、RNOH 0.82.30；Node 22.20.0、pnpm 10.19.0、Python 3、DevEco SDK/HDC。只声明实际验证的宿主和设备范围。
依据：本次用户确认；2026-10-21 总设计的三项开发闭环；现有 M4 范围及当前候选证据。

## 2. Must / Should / Could / Won’t

| 优先级 | 1.7.0 交付要求 |
| --- | --- |
| Must | 适配 create 与 Expo install/check/fix、config、prebuild、start、run、export；加包/移除、重复生成、锁文件重装、必要失败恢复；新增模块/插件按公开契约接入，不改 CLI 白名单 |
| Must | 原样 blank-typescript/default × npm/pnpm × Debug/Release；Release 断 Metro 冷启动；图片、字体、导航、Fast Refresh/reload 和前后台行为 |
| Must | 下表首批承诺能力、必要依赖与相关配置插件；源码/JS/类型/原生/发布物一致；候选身份与真实设备证据对应 |
| Must | 用户文件保护、受管资源移除、冲突及安装/生成失败恢复、准确设备选择与失败判定；SDK52 不回退及共享平台路径的受影响回归 |
| Should | 完整跨组合升级/回退、无运行影响的 SDK54 历史死代码清理；实际暴露的维护操作必须安全，不能把会损坏用户状态的问题后置 |
| Could | 完整自动点击覆盖、报告展示优化、历史证据全量便携重建；不能优先于实际产品缺陷 |
| Won’t | 非首批及非必要依赖的 M7 扩展；通用验证平台扩建；Expo Go、EAS、Updates、Dev Client 等原暂缓能力；SDK55+ |

SDK54 消费链不得依赖旧 CLI。仍可到达的旧 SDK54 入口必须明确退出或拒绝，不能以“清理后置”为理由保留错误支持承诺；SDK52 共享实现保留。

## 3. 首批能力边界

以下是必须交付的行为边界，不是整包全部 API 的支持声明。沿用现有 M4-A01～A07 必达条目，不借范围调整移除其中失败项。已有 M4→M7 转交项默认后置，原样 default 或下列承诺的必要依赖例外。

| 模块/底座 | 本版本承诺 |
| --- | --- |
| Core、Autolinking | 模块发现、同步/异步、事件、错误、原生 view、资源和 runtime/reload 隔离；陌生模块按公开契约接入 |
| Constants | 当前应用配置读取与生成、运行一致；首批模板和模块所需公开能力 |
| Asset | 声明资源、Metro/rawfile、加载与缓存、更新与移除、Release 离线资源 |
| Font | 声明式嵌入、运行时加载、renderToImage、原 M4 格式/错误契约、配置移除及无主资源清理；不能默默删除格式失败项 |
| SplashScreen、SystemUI、StatusBar | 相关配置及运行时行为；冷启动、前后台、主题、reload；平台 no-op 不算实现 |
| Linking、Router、Screens | 冷/热深链、onNewWant、嵌套路由、系统返回；原 M4 导航必达场景及原样 default 的 Tabs/Modal；已纳入必达的 Sheet/Drawer/方向缺陷须复验 |
| WebBrowser | 打开、取消、重复会话、关闭、销毁及原 M4 认证回跳契约；不默认承诺所有生产 OAuth 提供商 |
| ExpoImage | 原样 default 使用的属性、加载、显示和生命周期，以及已纳入首批必达的场景；其他属性/事件不自动升级为整包支持 |
| create、CLI、Metro、配置插件 | 上述开发流程及首批能力所需配置选项，用户 resolver/serializer 组合与平台隔离 |

Native Tabs、Router 服务端/Web 专属路径、Font Web 测试用途 unload 接口等已有 M7 转交，保持后续路线；若真实模板或首批必达依赖它们，按依赖纳入，不以名称批量排除。

发布前支持表必须逐 API/组件属性/事件/插件选项标注：已验收、未完成、后续版本或有依据的不适用。复用现有 scope 条目 ID 和来源，不重建一套全量扫描器。包名不代表整包支持。当前未通过项不得写成已支持。

## 4. 状态基线与历史兼容

M0/M0A/M1/M2/M3 在旧台账中已关闭；M4/M5/V 等有大量实现但尚未最终签收。11 月 14 日历史主机检查 1461 pass/0 fail/20 skip，不代表当前工作树或最终候选通过。

当前已知阻塞：Metro 四条 build/src 差异和 scope incomplete；Other 多应用采集与视觉断言闭环；当前候选完整设备矩阵及性能配对。Sheet/default/Image 等以最新候选复验为准，不照抄旧失败，也不以修复提交代替复验。

Metro 此前“保留 blocker、不改产品、不换基线”的专项决定未被本次范围授权自动撤销。先形成具体修复及影响方案；进入产品修改前按既有决定取得确认，其他工作继续。

保留 sdk54-stage-progress.json、definition 和历史 result 原样。旧 M7/M8 未完成仍未完成；1.7.0 新范围通过也不能标记旧全量 M8 完成。禁止改旧分母、删历史失败、直接翻转 scope.complete 或把 BLOCKED 写成 PASS。

## 5. 收敛任务与退出条件

### R1：固定可执行支持清单

负责：B/C 按原职责核对，单人时顺序执行。
落点：现有 scope-reviewed 输入、docs/releases/2026-10-28-sdk54-m4-scope-baseline.md、首批包 README 及新的版本支持表。

- [ ] 从现有范围记录提取原 M4 必达、default 必需和其实际依赖；逐项保留 ID、API/选项、候选来源、验收案例和真实状态。
- [ ] 对其余 M7 条目标记“后续版本”，保留原分类与前后范围差异，不记完成。scope incomplete 拆成当前必达未决与后置条目，不能整体忽略。
- [ ] 将公开支持声明与上述表对齐；必要底座/工具包不按业务包数量剔除。

退出：首批无范围歧义，用户可知道什么可用、什么未承诺；不是要求所有条目此时已通过。

### R2：候选一致性与单条真实设备闭环

落点：packages/@expo/metro-config、现有 release 打包工具；scripts/sdk54/abc/b-export-other-captures.mjs、c-verify-m4-captures.mjs、b-run-m4.mjs 及 ai-e2e 现有入口。

- [ ] 先提交 Metro 差异的具体修复建议及影响；保留专项决定边界。
- [ ] B/C 接合已有多应用 producer/consumer，先选一个真实场景贯通动作→原件→独立断言→report，再扩到其余场景。只修真实假 PASS/误拒绝，缺陷先写复现测试。
- [ ] 复用现有图像/布局判定，不以图片可解码或日志自报 PASS 替代视觉功能证据。
- [ ] 产品变化后重打受影响发行物；仅验收工具变化不强制重打产品。候选源码身份、工具身份分别固定，不自动提交以满足 clean-source。

退出：真实场景可完整验收，首批候选发布内容一致；设备不可用明确记 BLOCKED_DEVICE，不以扩建工具替代。

### R3：首批产品专项收尾

落点：首批 packages、已有模块夹具、a-verify-device/default/expo-image 等现有工具。

- [ ] 用当前统一候选复验资源、Sheet/Drawer/方向、原 default/ExpoImage、Core、Other；区分旧问题已修复、仍失败、未运行。
- [ ] 只修当前首批阻塞；每次真实缺陷先失败测试再最小修复，运行受影响检查。
- [ ] 固定输入未变化时复用来源材料，不无差别重建全部历史关系。必要来源/类型/包身份缺口不能跳过。

退出：首批专项均真实通过，未执行项不计完成；无需等待无关 M7 模块。

### R4：最终组合与维护安全验收

复用 package.json 的检查命令、test-release-install、现有设备 runner 与 benchmark-prebuild，不新建验证平台。

- [ ] 同候选新建 blank/default × npm/pnpm，验证安装及锁重装、配置、生成、命令、Debug/Release 八个首次构建运行案例；Release 断 Metro 冷启动。
- [ ] 验证配置/资源更新移除、用户扩展保护、冲突、中断恢复、错误设备、第三方模块及插件接入；SDK52 和受影响共享平台路径回归。
- [ ] 性能复用现有阈值和同机同工具配对要求：no-op≤30s且改善≥80%，配置变更≤45s且改善≥70%；首次/未构建重复回退≤max(20%,2s)，prebuild+增量构建回退≤max(10%,2s)。不因缩范围降低性能标准。
- [ ] 集成批次执行一次完整 pnpm check，保留 skip 原因；工具或产品后续变化按影响补验，不每个文档/报告切片重复全量检查。
- [ ] 输出本版本支持表、候选身份、逐项结果和必要原始证据。范围内无 FAIL/BLOCKED/NOT_RUN 才能签收。

退出：分别记录核心功能、安全与边缘、真实候选实跑、最终验收、版本关闭；仅宣布 1.7.0 明确范围完成，不宣布全量 Expo/M8 完成。发布操作仍需用户明确授权。

## 6. 执行减负与门禁调整

- 不再要求 M6 全部关闭才能开展模块工作；按实际依赖推进。完整跨组合升级/回退可后置，但已提供操作的正确性和恢复能力必须验收。
- 当前自动验收入口继续复用；完整自动化平台不再是产品交付的独立前置。可使用明确记录操作、候选/HAP/设备身份、原始输出及复核结论的人工设备验收，不冒称自动化 V 已完成，不修改旧 V 关闭规则。
- 普通修复只交付问题、差异、复现/回归、必要原件和未完成项；不强制每轮完整 HTML、单独设计或重建历史归档。最终汇总一次，已有机器输入格式继续兼容。
- 保留 B 产品/采集、C 独立验证的唯一写入者规则；同设备串行、共享构建产物不并发写。历史人员安排不得阻塞当前有授权的执行者。
- 不新增进度平台。任务表区分“已实现待验收”“真实通过”“环境阻塞”“后续版本”，不再把阶段 0% 当作开发进度或工期。
- 后续扩大范围须说明业务用途、依赖和验证成本；不能因扫描发现可实现能力便自动加入 1.7.0。
