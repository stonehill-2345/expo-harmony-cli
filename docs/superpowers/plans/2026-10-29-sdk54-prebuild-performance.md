# SDK54 prebuild 性能优化执行计划 v1

状态：A 批代码已落地，安全专项与仓库检查通过；编译后诊断仍未达性能门槛，整体为部分完成。详细结果见 [本轮验收报告](../../releases/2026-10-29-sdk54-prebuild-performance.md)。

配套设计：[prebuild 性能优化设计](../specs/2026-10-29-sdk54-prebuild-performance-design.md)。本轮定位为 M2 性能加固，在继续扩大模块适配前处理；expo-image 按 M7.4 原排期推进。

## 执行顺序

1. 固定候选与隔离基线 → 验证：重现编译后慢路径，分清扫描、哈希、合并、复制及提交耗时。
2. 实施 A 批按需读取、流式哈希、独立复制与减少重复写入 → 验证：安全回归先红后绿，比较完整输出及资源消耗。
3. 对照性能门槛决定是否进入 B 批缓存分离 → 验证：达标就结束优化；未达标且缓存确为瓶颈，先闭合归属、并发、日志与恢复设计。
4. 验收最终候选 → 验证：npm/pnpm 真实消费、增量构建、nova 16 Pro Debug/Release 与证据归档。

## P2：条件性 B 批设计门与实现

进入条件：A 批安全回归通过、性能仍未达标，并且计数显示已确认缓存仍是主因。进入本批不等于批准忽略目录或删除文件。

- [ ] 在设计文档追加实际缓存归属判据、旧项目回退规则、普通生成/clean/no-build-cache 行为表。
- [ ] 追加生成与构建的锁时序，覆盖 CLI 内部调用和外部 DevEco 写入；无可靠保护时使用保守路径。
- [ ] 列出“写日志前后、每个缓存 rename 前后、旧树备份前后、新树安装前后、提交后清理”的故障状态表；每一项明确保留哪些路径、怎样恢复以及何时拒绝恢复。
- [ ] 确定新事务日志版本和迁移测试。先实现旧/新日志读取与恢复，再启用生成新日志的代码。
- [ ] 用真实子进程复现：缓存目录被替换成软链、目录内人工文件被改、生成与构建并发、缓存移动一半退出、安装后再被编辑、回滚时同名路径冲突；验证没有静默丢失或覆盖。
- [ ] 只有上述条件通过，才实现缓存快速路径并扩大 CLI 锁协调。若无法保证原语义，保留 A 批，报告未达标原因，不标记优化完成。

可能新增文件是一个共享的工程路径分类模块；只在扫描、合并、事务确需共享时引入。CLI 的 `harmony/build.ts`、`run/harmony/runHarmonyAsync.ts`、`prebuild/harmony/prebuildHarmonyAsync.ts` 仅在 B 批锁/缓存集成确有需要时修改。

## P3：最终验收

- [x] 同一候选对 npm、pnpm 各创建真实消费工程，核对安装身份与文件字节；不能通过链接源码目录证明发行包行为。
- [ ] 按设计中的五次样本规则比较：编译后无变化中位数至少改善 80% 且 ≤30 秒；配置变更至少改善 70% 且 ≤45 秒；首次生成与后续构建无规定之外的回退。
- [ ] 对新旧实现的生成内容、文件模式、状态、用户文件进行独立比较；纯性能修改应保持语义一致。B 批允许差异必须逐项对应事先确定的缓存协议。
- [ ] 对配置变更后构建的 HAP 检查实际新资源/值，避免缓存命中掩盖更新；普通重复 prebuild 后记录真实增量编译耗时与缓存是否复用。
- [x] nova 16 Pro：blank Debug 首屏、修改 App.tsx 热更新、冷启动；全新 blank Release 在关闭本轮 Metro 并移除本轮转发后启动。设备窗口、UI 文本、截图文件格式/非空、日志与包指纹共同核验。
- [ ] default 保持原模板与依赖，验证 prebuild/构建不回退；已知 ExpoImage 缺口继续记为 M7.4 阻塞，不用本轮性能结果关闭 default 全功能。
- [x] 定稿后运行 `pnpm check`、`pnpm sdk54:release:check` 与 `git diff --check`；修复相关失败后再运行受影响检查。

## 停止扩张与回退

安全用例失败即停止进入下一批；原数据和失败证据保留。A 批维持旧协议，便于撤回代码优化；B 批引入新协议后先完成/恢复未结束事务，再回退实现，不能让旧程序处理不认识的新日志。

本轮完成后仍未达门槛，结论写“部分完成/目标未达成”，说明主要成本和下一步，不按测试数量替代性能结果。候选发布、git add、提交和推送均不属于本计划的自动执行步骤。
