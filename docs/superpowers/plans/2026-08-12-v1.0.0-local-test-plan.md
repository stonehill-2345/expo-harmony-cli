# expo-harmony-cli 1.0.0 本地测试方案

## 1. 测试目标

验证核心链路：

```text
create -> install -> prebuild --platform harmony -> sync -> start:harmony -> bundle:harmony:release
```

本方案只覆盖本地 CLI、Node.js、Metro 和文件产物，不要求真实设备、DevEco Studio 或 HAP 签名环境。

## 2. 前置条件

```bash
cd /Users/wum/2345/expo-harmony-cli
pnpm install
```

建议 Node.js 18+、pnpm 和可用的 npm 缓存。

## 3. 自动化回归

```bash
pnpm build
pnpm type-check
pnpm test
```

重点模块：

```bash
pnpm test -- pkg-manager
pnpm test -- install uninstall
pnpm test -- injector
pnpm test -- autolinking standalone
pnpm test -- scan-list
pnpm test -- pack-files
```

预期构建、类型检查成功，全部 Vitest 测试通过。

## 4. 包管理器和 codegen

```bash
node - <<'NODE'
const { runScriptCmd } = require('./dist/lib/pkg-manager');
for (const pm of ['pnpm', 'npm', 'yarn', 'bun']) console.log(pm, runScriptCmd(pm, 'codegen'));
NODE
```

预期：`pnpm codegen`、`npm run codegen`、`yarn codegen`、`bun run codegen`。

同时验证 `pnpm-lock.yaml`、`package-lock.json`、`yarn.lock`、`bun.lockb` 的识别，以及 `--npm/--yarn/--bun/--pnpm` 显式参数优先于 lockfile。

## 5. create 和 prebuild

```bash
TEST_ROOT="$(mktemp -d)"
cd "$TEST_ROOT"
node /Users/wum/2345/expo-harmony-cli/dist/index.js create demo-app
cd demo-app
node /Users/wum/2345/expo-harmony-cli/dist/index.js prebuild --platform harmony
```

检查：

```bash
test -f package.json
test -f metro.config.js
test -f harmony/AppScope/app.json5
test -f harmony/entry/oh-package.json5
test -f harmony/entry/src/main/ets/RNOHPackagesFactory.ets
test -f harmony/entry/src/main/cpp/RNOHPackagesFactory.h
test -f harmony/entry/src/main/cpp/autolinking.cmake
rg -n "localhost:8081|8081" harmony metro.config.js
```

## 6. Metro 和端口

```bash
pnpm start:harmony
HARMONY_METRO_PORT=9000 pnpm start:harmony
```

分别确认默认使用 8081，自定义端口 9000 同时用于 Metro 参数、LAN 地址和 hdc 转发提示。使用 `0`、`65536`、`abc` 等非法值时应回退 8081。

手工创建自定义 `metro.config.js` 后重新执行注入，确认内容不被整体覆盖；CLI 托管配置应包含 `// expo-harmony-cli:managed` 标记。

## 7. scan

```bash
node /Users/wum/2345/expo-harmony-cli/dist/index.js scan
node /Users/wum/2345/expo-harmony-cli/dist/index.js scan --apply
```

默认命令只输出报告，不修改 `package.json`、`patches/`、`shims/`、`.expo-harmony/`；`--apply` 才落盘。连续执行两次 `--apply` 应保持幂等。

## 8. autolinking

```bash
pnpm test -- autolinking standalone
```

覆盖有效 HAR 链接、HAR 缺失或为空时 `skipped`、多包稳定排序、用户依赖保留和重复 sync 幂等。

## 9. release bundle

```bash
pnpm install
pnpm bundle:harmony:release
BUNDLE="harmony/entry/src/main/resources/rawfile/bundle.harmony.js"
test -s "$BUNDLE"
test -d harmony/entry/src/main/resources/rawfile/assets
```

临时移走 `harmony/entry` 后重新执行，预期返回非零状态并提示先执行 prebuild；旧 bundle 不应作为有效产物保留。

## 10. 发布物

```bash
pnpm build
pnpm test -- pack-files
pnpm pack --dry-run
```

发布物应包含 `dist/`、`templates/harmony/`、模板 manifest 和 `content/`，不应包含 `.hvigor/dependencyMap/`、`.idea/`、本机绝对路径或 `docs/superpowers/`。

## 11. 验收标准与边缘场景

- 无 lockfile 默认 pnpm，显式参数覆盖 lockfile。
- 端口非法回退 8081，合法自定义端口全链路一致。
- 自定义 Metro 配置不被静默覆盖。
- 缺 HAR 不生成虚假 autolinking 注册。
- scan 默认只读，`--apply` 修改且重复执行幂等。
- release bundle 失败返回非零状态并清理陈旧产物。
- `pnpm build`、`pnpm type-check`、`pnpm test` 全部通过。

DevEco Studio 构建 HAP、设备安装、签名和提审包属于后续 HarmonyOS 集成验收，不作为本地 CLI 测试阻断条件。
