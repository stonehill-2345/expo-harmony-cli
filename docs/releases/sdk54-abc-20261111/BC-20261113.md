## 效率与停止边界

- B/C 使用独立 checkout、消费者和输出目录；共享输入只读。设备提前分配时间段：B 修复自验后交 C 独立执行；同机性能期间另一方只做编辑/阅读，不编译测试。
- 先跑受影响专项定位问题，再冻结并做全矩阵，避免每次小修复重跑全部。候选 hash 改变必须记录影响分析并重跑受影响项，无法证明范围时重跑全矩阵；旧 PASS 不跨身份迁移。
- Should：整理可移植交接原件、清晰的失败复现及补测顺序。Could：不阻塞最终目标的报告便利性。Won't：新建通用静态分析框架、重复验证平台、全量实现未纳入必达的 ExpoImage/M7 能力。
- 无“等待 A”阻塞；真实阻塞只能是缺准确原件、设备/环境、未决范围或必要 Git 授权等。发现实现未完成归责任方继续开发，不能写成外部阻塞。
- 完成以同一正式候选的必达功能、公开关系、矩阵、性能和独立证据为准。源码完成、主机测试、LOCAL 设备成功、最终验收与阶段关闭分别报告，禁止用总百分比替代门禁。
